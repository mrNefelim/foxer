# Требования к Telegram-боту Forex

## Единственная стратегия

С 18.11.2026 по запросу пользователя приложение использует только Swing.
Удаляется отдельный FVG-движок: его расчёт, сигналы, конфигурация, редактор
параметров, CLI и PDF. Зоны FVG, фракталы и гэпы внутри алгоритма Swing
остаются частью Swing и не являются вторым движком.

Рабочие правила — `strategy/swing-rules.json`; `example.json` содержит тот же
публикуемый формат и значения. Единственный путь сервиса — `STRATEGY_PATH`.
`SWING_STRATEGY` и `PRICE_TICK` больше не поддерживаются и явно отклоняются.
Запуск и `check-config` по умолчанию читают Swing JSON. Подстановки старого
FVG JSON, встроенных правил или примера при ошибке нет.

Корень JSON содержит непустую карту `instruments`: символ из шести заглавных
ASCII-букв → полный `SwingConfig`. Допускаются корневой строковый `comment`
и объект `comments` со строковыми пояснениями. Дубли ключей, неизвестные поля,
неизвестные семьи и неправильные типы отклоняются. Торговые параметры
текущего профиля R010 сохраняются без изменений. `comment` и `comments` не
влияют на расчётный хеш. Проверка всех параметров использует контракт Swing,
а не удалённую схему FVG v2. Диагностический вывод `describe-config` показывает
пути пояснений, но скрывает их текст; протокол разбора комментариев получает
исходный документ с пояснениями. Периоды ATR/планов/поиска стопа положительны,
RR и предел цели положительны и конечны, отступ/издержки неотрицательны,
часы входа уникальны в 0..23; границы окон диапазона согласованы.

## Продукт и общие компоненты

Бот получает индексные котировки Upscale и сообщает торговые события Swing
в настроенную группу Telegram. Ордеры брокеру автоматически не отправляются.
Сохраняются календарь, агрегатор W/D/H4, строгий импорт MT5/SQLite, контроль
источников и пропусков, HTTP-адаптеры, очередь комментариев, OpenAI-анализ,
атомарное изменение JSON, журнал событий и outbox. Работа с сетью проверяется
подменами; живое подключение не является частью этой миграции.

## Торговые правила Swing

Действующий набор правил. Состав: планы «тренд» и «коррекция», вход,
стоп, тейк и исполнение; торговля в боковике; выход по индексу доллара.

| Тема | Правило |
|---|---|
| Свечи | H4, D и W по сетке источника; неделя — с понедельника 00:00 времени сетки. Свечи без котировок не создаются. |
| Фрактал | Свеча, у которой максимум (минимум) выше (ниже), чем у обеих соседних; известен после закрытия следующей свечи. Снят, когда более поздняя свеча прошла его цену. |
| Зона (FVG) | Разрыв между первой и третьей свечой тройки, без минимального размера. Жива, пока свеча не закроется за дальней границей; это закрытие — инверсия зоны. |
| Структура | Вверх: последние два верхних и два нижних фрактала последовательно выше; вниз — последовательно ниже; иначе структуры нет. |
| ATR | Среднее (максимум − минимум) последних `atr_period` свечей. |
| План «тренд» | На закрытии недели при недельной структуре: последняя живая недельная зона по структуре, лежащая за ценой закрытия, затронута этой неделей, и есть ближайший неснятый недельный фрактал по ходу. Цель — этот фрактал. Подтверждение — на H4. |
| План «коррекция» | На закрытии недели при недельной структуре: неделя прошла недельный фрактал по ходу структуры, которого предыдущая неделя не проходила. Направление — против структуры, цель — ближняя граница последней живой недельной зоны по структуре. Подтверждение — на D; если между последним дневным закрытием и целью нет живой дневной зоны против плана — на H4. |
| Повтор плана | План с тем же видом, направлением и точкой отсчёта не создаётся, пока прежний не завершён. |
| Подтверждение | На таймфрейме подтверждения закрылась свеча, образовавшая зону по плану или инвертировавшая зону против плана. |
| Вход | После подтверждения: закрылась свеча H4, образовавшая зону по плану, и час её закрытия входит в `entry_close_hours`. |
| Стоп | Ближайший фрактал H4 за защитной стороной (за меньшим из цены входа и границы зоны для покупки, зеркально для продажи) среди последних `stop_lookback_h4_bars` свечей; если его нет — дальняя граница зоны. Отступ `stop_buffer_atr` × ATR(H4). |
| Тейк и способ входа | Если до цели не меньше `rr_fixed` риска — вход по рынку; тейк на `rr_fixed`, а при `take_profit=target` — на цели, но не дальше `rr_target_cap`. Если меньше — лимитная заявка в точке, от которой до цели ровно `rr_fixed` при том же стопе; если эта точка хуже текущей цены, сделки нет. |
| Издержки | Цена исполнения хуже на `cost` в сторону сделки. |
| Лимитная заявка | Исполняется в любое время при касании цены. Снимается, если цена дошла до тейка раньше входа или план завершён. |
| Выход | Стоп или тейк; при обоих в одной минуте — стоп. Результат стопа −1R. |
| Срок и отмена плана | План без открытой сделки, включая план с ожидающей лимитной заявкой, завершается на `plan_days`-м дневном закрытии после создания. На этой границе заявка отменяется до проверки исполнения по следующей котировке. После исполнения срок плана больше не закрывает сделку. «Тренд» завершается недельным закрытием за зоной, «коррекция» — дневным закрытием за ценой фрактала. |
| Начало работы | До `start` свечи только накапливаются; планы и сделки не создаются. |
| Свечи бота | В боте и в бэктесте по базе правила получают свечи, которые строит бот (`feed::Aggregator`), включая неполные — с разрывом котировок или отключением внутри. Неполная свеча строится только из пришедших котировок, пропуски не заполняются. Время свечей переводится в сетку источника: время Нью-Йорка + 7 ч (00:00 сетки — 17:00 Нью-Йорка). Цены — индексные цены базы, делённые на 1 000 000. |

Торговля в боковике (`range.enabled`):

| Тема | Правило |
|---|---|
| Когда ищется диапазон | На каждом закрытии H4, если закрыто больше `range.min_h4_bars` свечей H4, диапазона сейчас нет и ATR(D) больше нуля. |
| Диапазон | Самый длинный отрезок из последних закрытых H4 (без текущей), от `range.window_min` до `range.window_max` свечей, у которого высота (максимум − минимум) не больше `range.height_max_atr_d` × ATR(D). Высота должна быть не меньше `range.height_min_atr_d` × ATR(D). Границы — максимум и минимум отрезка. |
| Импульс перед диапазоном | `range.impulse_bars` свечей H4 прямо перед отрезком прошли не меньше `range.impulse_min_atr_d` × ATR(D) и не меньше `range.impulse_min_ratio` × высоты диапазона. Иначе диапазон не принимается. |
| Один диапазон на импульс | Импульс засчитывается, только если начался больше чем через `range.impulse_bars` свечей после начала импульса предыдущего принятого диапазона. |
| Конец диапазона | Закрытие H4 дальше `range.break_fraction` × высоты за любой границей. После закрытия сделки в боковике (тейк или стоп) диапазон ищется заново. |
| Сигнал продажи у верхней границы | Закрытие H4 внутри диапазона и одно из двух: максимум свечи выше границы не меньше чем на `range.wick_min`, либо предыдущая свеча закрылась выше границы. Покупка у нижней — зеркально. Сначала проверяется верхняя граница; за одно закрытие — не больше одной сделки. |
| Ограничения | Одновременно не больше одной сделки в боковике (с заявкой). От одной границы диапазона — не больше `range.max_stops_per_border` стопов. Вход — только на закрытии H4 из `entry_close_hours`. |
| Стоп | За экстремумом девиации — максимумом (минимумом) текущей и предыдущей свечи — с отступом `stop_buffer_atr` × ATR(H4). |
| Тейк и способ входа | Цель — противоположная граница. Если до неё не меньше `rr_fixed` риска — вход по рынку, тейк на `rr_fixed`. Иначе лимитная заявка в точке, от которой до цели ровно `rr_fixed`; точка должна лежать внутри диапазона. Исполнение, издержки и выход — как у остальных сделок. |

Выход по индексу доллара (`reference_exit`, для инструмента, у которого задан знак):

| Тема | Правило |
|---|---|
| Индекс | Синтетический индекс доллара по формуле ICE: 50.14348112 × EURUSD^−0.576 × USDJPY^0.136 × GBPUSD^−0.119 × USDCAD^0.091 × USDSEK^0.042 × USDCHF^0.036. Открытие и закрытие минуты — по открытию и закрытию пар; максимум и минимум — по тем экстремумам пар, которые двигают индекс в нужную сторону. Минута индекса есть, только если есть эта минута у всех шести пар. |
| Расчёт по индексу | По минутам индекса работает отдельный экземпляр правил «свинг» со своими параметрами. Он не торгует, а только отмечает события: цель плана «тренд» или «коррекция» достигнута (первое касание, время — минута касания, направление — направление плана), открыт вход в боковике (время — закрытие свечи, направление — направление входа), план подтверждён (время — закрытие свечи). |
| Знак | Направление индекса, которое соответствует сделке по инструменту: −1 для EURUSD (индекс вниз — евро вверх). |
| Выход | В каждой минуте до исполнения заявок открытая сделка закрывается по закрытию минуты, если среди последних `reference_exit.recent_events` событий индекса, известных к этой минуте, есть «цель достигнута» или «вход в боковике» с направлением сделка × знак и временем строго после исполнения сделки и не позже этой минуты. Результат — по фактической цене; закрытие сделки в боковике завершает диапазон, но стопом не считается. |

### Исследовательское расширение правил по инструментам

Текущий swing остаётся совместимым семейством `legacy_swing`. Для нового
исследовательского семейства `trend_pullback` его параметры задаются отдельно
для каждой пары; рабочий JSON без явного выбора семейства продолжает означать
legacy swing. Неизвестное семейство и неполные параметры нового семейства
отклоняются. Переключение пары не меняет конфигурации остальных пар.

`trend_pullback` — исследовательское правило, а не ранее согласованное
пользовательское условие. Оно использует только закрытые H4 свечи, построенные
тем же агрегатором и в той же временной зоне, что и swing. Быстрая и медленная
EMA считаются по H4 close; каждая EMA инициализируется средним первых `period`
закрытий, далее `EMA[t] = alpha*close[t] + (1-alpha)*EMA[t-1]`,
`alpha=2/(period+1)`. Пока нет полной истории для медленной EMA, сигналов нет.
В JSON инструмент сохраняет все общие swing execution-поля и задаёт
`"family": "trend_pullback"` вместе с обязательным
`"trend_pullback": {"fast_ema_bars": ..., "slow_ema_bars": ...}`.
Legacy задаётся либо отсутствующим `family`, либо явным
`"family": "legacy_swing"`; в обоих случаях параметры
`trend_pullback` отсутствуют. У `trend_pullback` поле параметров обязательно;
несогласованные сочетания и неизвестные поля отклоняются.

`cost` во всех семействах — конечное неотрицательное число в единицах цены;
отрицательные и неконечные значения конфигурации отклоняются. Для legacy
семейства это общее ограничение не меняет расчёт уровней и исполнение. В
`trend_pullback` дополнительно проверяются конечность рассчитанного входа,
стопа, риска и цели, строго положительные цены входа/стопа/цели и
положительный риск в направлении сделки. Сделка не создаётся при переполнении
или неположительном ценовом уровне. Для этой семьи нет произвольного верхнего
предела `cost`: проверяются конкретные рассчитанные уровни. При сравнении
×1/×2/×3 исходный положительный `cost` умножается на коэффициент; обе модели
используют одинаковый коэффициент и единицу риска.

Для смешанного файла инструментов `comments` поясняет объединение всех leaf
ключей, используемых всеми парами. Семейство определяет свои обязательные
поля: у legacy поле `family` необязательно, а `trend_pullback` запрещено;
новое семейство требует оба поля и оба EMA-параметра. Сначала десериализуется
соответствующая конфигурация, затем выполняется семейная и общая валидация;
параметр другой семьи или пропущенный обязательный параметр отклоняется.
Комментарии не заставляют разные пары выбирать одинаковую стратегию.

Во втором поисковом раунде новый `trend_pullback` JSON явно задаёт
`trend_pullback.max_open_positions: 1`. Это положительное целое; ноль,
отрицательное, `null` или значение другого типа отклоняется. Поле остаётся
необязательным при чтении прежних JSON и snapshots: если ключ отсутствует,
сохраняется прежнее
неограниченное поведение. Параметр действует только на `trend_pullback`; legacy
не ограничивается. Каждая допущенная сделка сохраняет исходный риск 1R.

Лимит считается по инструменту, а не по экземпляру стратегии. Pending и Active
сделки текущей и retired-конфигураций занимают место до отмены или закрытия;
их существующие уровни и сопровождение не меняются. Если при смене конфигурации
занятых слотов уже больше нового лимита, позиции и заявки не отменяются и не
закрываются принудительно; новые входы блокируются до освобождения слота.
Переход Pending → Active сохраняет тот же слот, отмена заявки или завершение
сделки освобождает его в принятом порядке событий. При полном лимите новое
подтверждённое событие `trend_pullback` пропускается, не ставится в очередь и
не исполняется позже. EMA и остальной контекст обновляются и во время блокировки. Допуск
проверяется до обработки выходов текущей минуты: позиция, закрываемая в той же
минуте, освобождает место только для следующего сигнала.

Покупка возникает на закрытии H4 `t`, если быстрая EMA выше медленной как на
предыдущем закрытии, так и сейчас; предыдущий H4 close был не выше своей
быстрой EMA, а текущий close выше своей быстрой и медленной EMA. Продажа —
зеркально: быстрая EMA ниже медленной на предыдущем и текущем закрытиях,
предыдущий close не ниже быстрой EMA, текущий close ниже обеих EMA. Требование
уже установленного тренда перед возвратом исключает начальный cross из боковика.
Так
подтверждается возврат по тренду после отката через среднюю; решение не
использует незакрытую свечу или её будущие экстремумы. Один сигнал имеет
стабильный ключ из пары, семейства, направления и времени закрытия H4.

Сигнал становится рыночным входом при первом наблюдении закрытия сигнальной H4
свечи в ту же минуту, что и её `end` (`floor(now/60)=floor(end/60)`). Цена,
согласно общему legacy исполнителю, задаётся close сигнальной H4 свечи, а
`fill_t` — фактическое время наблюдения `now`; текущие или будущие high/low M1
не участвуют в выборе цены входа. Если минуту границы пропустили, бар разрешено
учесть для контекста, но сигнал по нему не исполняется задним числом. Цена входа
получает существующую неблагоприятную `cost` на входе. Стоп покупки — минимум
low последних 10 закрытых H4 свечей,
включая сигнальную, минус 0.1 ATR; для продажи зеркально максимум high плюс
0.1 ATR. ATR — простое среднее `high-low` последних 14 закрытых H4 свечей,
включая сигнальную; без полного периода или при невалидном расстоянии до стопа
сделки нет. Цель — 2R, где R — расстояние фактического входа до исходного
стопа. Сопровождение и закрытие используют общий lifecycle swing.

Параметры fast EMA в JSON ограничены значениями 8, 12, 16, 20 баров; slow
EMA — 32, 40, 50 баров; допустимы только `fast < slow`. Общие JSON-поля
`atr_period`, `stop_lookback_h4_bars`, `stop_buffer_atr`, `rr_fixed` и
`take_profit` для этой семьи должны соответственно задавать 14, 10, 0.1 и 2,
`fixed`. Код не подставляет эти значения вместо отсутствующих параметров.
Это заранее ограниченное пространство первого исследования, а не гарантия
результата.

Для сравнения baseline и нового семейства используется одинаковый legacy
lifecycle, одинаковая единица R и те же цены/издержки. `cost` применяется
неблагоприятно один раз при входе, как в существующем `Swing::minute`; варианты
×1/×2/×3 умножают его одинаково для baseline и кандидата. Стоп и цель
проверяются по наблюдаемым M1 high/low; если оба достижимы в одной минуте,
первым считается stop. Stop исполняется на заданном стоп-уровне даже при гэпе
через него: модель не имеет M1 open в общем API и не оценивает дополнительное
проскальзывание гэпа. Target исполняется на целевом уровне. Это явное
ограничение исторической модели; изменение его требует отдельной общей модели
исполнения и повторного baseline.

После смены семейства опубликованные Pending/Active сделки продолжают
сопровождаться на исходных уровнях, с исходной конфигурацией исполнения и без
повторной публикации. Новое семейство начинает создавать сигналы по новой
конфигурации; старые снимки без поля семейства читаются как legacy swing.

Stable ID сигнала остаётся зарегистрированным после Stop, Target, Cancelled или
другого терминального события. Прогрев после рестарта или смены конфигурации не
переиздаёт и не возвращает под сопровождение уже зарегистрированный ID.
Регистрация учитывает как подтверждённые Telegram-сообщения, так и исходящие
сообщения в очереди доставки; чтение очереди не меняет её статус, порядок или
содержимое. Это правило распространяется и на терминальное сообщение, которое
ещё не было доставлено.

### Применённый профиль swing после R010

По зафиксированному правилу R010 выбрана конфигурация EURUSD baseline,
GBPUSD baseline и USDJPY исходный qmc-018. Для USDJPY используются
`rr_fixed=2.25`, `take_profit=target`, `rr_target_cap=3`, `plan_days=7`,

совместимый `legacy_swing`. Сохранены `start=1598918400` и `cost=0.01`.
EURUSD и GBPUSD остались исходными. Источник профиля — сохранённый
`qmc-018/USDJPY.json` SHA-256
`6ea9e172228b2ebc4d2b6d4948bd77dbcdfdf06539d4b66febf374005ab292f1`.

Проверка на V3 release `11eb05973d054d6f9e8aaa56cce76ef4c540be226fe8315eccc5fbe1ac3ae8e0`

## Состояние, переход и изменение правил

Поддерживается SQLite v4. Старые снимки приложения внутри этой схемы читаются
без FVG-десериализатора: поле старого engine игнорируется, а агрегатор,
текущий и retired Swing, опубликованные уровни, stable ID, offset, очередь
комментариев, привязки Telegram и ожидающие сообщения Swing сохраняются.
Сетка календаря не меняется. Устаревшие неотправленные сообщения FVG и
недельные уведомления FVG снимаются с доставки; история доставок не удаляется.
Повтор входного события и повторный запуск после перехода не создают новых
сделок и не дублируют торговые сообщения. Незавершённая старая операция правки
FVG не применяется к Swing: запуск явно сообщает о необходимости завершить
её предыдущей версией, не изменяя файл правил.

Новые правила читаются целиком до изменения состояния. Изменение параметров
пары создаёт новый Swing-контекст; ранее опубликованные Pending/Active
продолжают сопровождаться с исходными уровнями и конфигурацией, в том числе
после удаления пары из набора новых входов. Остальные пары не переинициализируются.
Прогрев не публикует завершённые исторические сделки; открытые позиции
при первой загрузке обозначаются «Открыта до запуска». Комментарии не перезапускают расчёт.

Telegram-правки разрешены только по существующим путям действующих параметров
`/instruments/<SYMBOL>/...` и корневых пояснений. Семейство алгоритма и время
старта меняются только в файле; массив часов редактируется по существующим
индексам. Новые поля и структуры через Telegram не добавляются. Весь кандидат проходит проверку
Swing до атомарной записи JSON. Контекст содержит именно Swing-сделку и её пару. Структурированный контекст
опубликованных Swing-событий сохраняется и после закрытия сделки, удаления
старого расчётного экземпляра и перезапуска. Для старых снимков без такого
контекста сохраняется доступный текст сообщения; недостающие поля не выдумываются.
Комментарии к прежним FVG-сигналам не меняют Swing: бот объясняет, что сигнал
относится к удалённой стратегии. Сеть, хранение вложений, FIFO и восстановление
незавершённой записи сохраняют прежние гарантии. exactly-once доставки Telegram
при потерянном сетевом ответе не обещается; повтор локальной обработки идемпотентен.

При остановке котировок новые входы не создаются, существующие позиции
сопровождаются по фактически пришедшим ценам. Статус и H4-лог используют
состояние Swing; FVG-направления и FVG-планы больше не вычисляются.

## История и бэктест

`swing-history` читает проверенные подготовленные UTC/index M1, строит свечи
общим агрегатором и переводит время в торговую сетку America/New_York + 7 часов.
`swing-replay` читает MT5 M1. Обе команды требуют корректные конечные цены,
строго возрастающее время и непустую историю; источник и хеши сохраняются.
`dxy-build` остаётся инструментом Swing reference_exit и использует только
пересечение наблюдаемых минут шести пар. reference_exit пока не поддерживается
в живом боте и `swing-history`; включение завершается явной ошибкой.

FVG-CLI, архивный FVG replay и его старый PDF удаляются. `--help` описывает
только Swing-команды. `--report-only DIR` строит `report.pdf` из текущего
Swing `report.json`; повторный replay для этого не нужен. Существующий PDF
не перезаписывается молча. Параметры и сделки для отчёта берутся из сохранённого
запуска, а не из тестовых фикстур или старого FVG results.json.

`scripts/swing_report.py` сохраняет точность дробных торговых цен, строго
обращает DST-сетку, исключает входы за общей границей и цензурирует поздние выходы.
Переоценка использует наблюдаемые закрытия M1 на общей сетке, без заполнения
пропусков. R — сумма индивидуальных единиц первоначального риска, не проценты
и не капитал счёта. PDF показывает закрытый и переоценённый итог, MTM-просадку,
открытые позиции, результаты по парам/годам, параметры и происхождение данных.
График прорежен до дневных отметок с сохранением экстремумов; скалярная просадка
считается по полному минутному ряду. Это моделирование на исторических котировках,
а не брокерские сделки. Исходные данные и принятый отчёт не переписываются
при удалении FVG-кода. Новый подбор параметров и исторические оптимизации
в эту задачу не входят.

## Данные и поставка

Цены источника хранятся в миллионных долях, время — UTC. Общий агрегатор
строит только наблюдавшиеся свечи, включая признак неполноты; Swing получает
все закрытые свечи по прежнему алгоритму. `data::inspect` показывает последние
закрытые W/D/H4 (до 200 последних свечей каждого таймфрейма) и покрытие
по инструментам Swing без FVG context-параметров. Без явного символа выбирается
EURUSD, если она настроена, иначе первая пара рабочего JSON.
Контроль источников, SQLite application_id/user_version и read-only анализ
сохраняются. Ключи, модель OpenAI, группа, таймауты и пути БД находятся в `.env`.
Данные не включаются в Git, пропуски не заполняются предположениями.

Docker — единственное обязательное окружение Rust разработки/сборки/тестов.
Версии образов и зависимостей закреплены. Сервер автоматически не перезапускается
и не обновляется; обновление локального кода не считается проверкой live-исполнения.
Общий портфельный ограничитель D4 остаётся не реализованным проектом.

## Котировки Upscale и индексные сигналы

По согласованию от 12.11.2026 текущий источник — Upscale, демо-счёт.
run требует UPSCALE_API_KEY и ровно один активный API-enabled demo account.
Все инструменты JSON запрашиваются одним GET каждые 2 секунды после завершения
предыдущего запроса. Никакие ордера не отправляются.

Сопоставление: EURUSD → EUR/USD, GBPUSD → GBP/USD, USDJPY → USDJPY/USD.
Проверяются ticker/baseAsset/quoteAsset, уникальность рынка, цена, время и
флаги рынка. Неизвестные, неоднозначные, некорректные и устаревшие открытые
рынки отклоняются. Ошибка одной пары не блокирует остальные.

Расписание `schedule` читается из того же ответа для каждой пары. При
`inPause=true` индекс не передаётся в расчёт; после окончания перерыва
передаются только свежие котировки, прошедшие прежние проверки. `schedule=null`
означает круглосуточный рынок. Опрос продолжается с прежним интервалом, без
отдельных запросов расписания. Начало и конец планового перерыва не вызывают
сообщений в чат или уведомлений о потере/восстановлении котировок.

probe-upscale <env-file> однократно читает все активные демо-счета и их рынки,
без Telegram/OpenAI/SQLite. Нет подходящего счёта — ошибка. Вывод содержит
индексные цены fp9, UTC-время в миллисекундах и статусы, без ключа и персональных
данных. Ключ необязателен для офлайн-команд; указанные пустые значения,
дубликаты и неизвестные имена env отклоняются.

## Торговые методы адаптера Upscale

Отдельные методы адаптера Upscale позволяют открыть позицию по рынку,
прочитать открытые позиции счёта и закрыть заданный объём позиции по рынку.
Параметры передаёт вызывающий код: счёт, рынок, направление, сумма резерва и
плечо для открытия; идентификатор позиции и объём базового актива для закрытия.
Все суммы, объёмы и плечо — строки fp9 без преобразования через float.
Методы возвращают статус ордера и ошибку исполнения, не приравнивая принятие
ордера к исполнению. Ключ идемпотентности задаётся вызывающим кодом;
автоматических повторов торговых запросов нет.
Эти методы не подключены к сигналам или CLI. Работающий бот по-прежнему
не отправляет ордера; стратегия, БД и уведомления не меняются.
