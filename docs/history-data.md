# Исторические данные Swing

Swing использует минутные OHLC с явным происхождением. Наличие файла не
доказывает полноту истории. Пропущенные минуты не заполняются, источник,
часовой пояс и единицы сохраняются при подготовке, импорте и экспорте.

## Подготовленные минуты

Набор для `swing-history` содержит `quality-report.json` и каталог `prepared/`.
Архивы тиков и `manifest.json` для этого пути не нужны. В отчёте качества
обязательны совпадающий `symbol`, непустой `source`, `timezone="UTC"`,
`price_basis="index"` и `outputs` с контрольными суммами файлов. Подготовщик
также сохраняет `gaps`, `missing_months`, происхождение и размер каждого файла.

Читаются перечисленные в `outputs` файлы `<SYMBOL>-M1-*.csv`, отсортированные
по имени. Перед чтением каждого файла проверяется SHA-256. Точный заголовок:

```csv
timestamp_utc,timestamp_ms,bar_end_utc,open,high,low,close,quote_count,gap_before_minutes
```

Время — начало целой минуты UTC; `timestamp_ms` соответствует ему, конец
минуты — через 60 секунд. Положительные OHLC имеют не более шести знаков
после запятой и согласованные границы; внутри приложения цены хранятся в
миллионных долях. `quote_count` положителен. Строки должны идти строго по
возрастанию времени, включая границы файлов; дубликаты и пересечения
отклоняются. Требуются хотя бы один подходящий файл и одна минута.

`swing-history` читает весь набор. Минуты до `start` из конфигурации дают
контекст W/D/H4, но не создают планы и сделки. Короткая корректная история,
на которой нет сигналов, успешно создаёт CSV сделок только с заголовком.
Свечи строит общий с ботом `feed::Aggregator`; неполные свечи сохраняют
только фактически пришедшие котировки.

## Подготовка MT5 и импорт в SQLite

```text
forex-bot prepare-mt5 EXPORT.csv NEW_ROOT SYMBOL SOURCE
forex-bot import-history DATABASE.sqlite NEW_ROOT SYMBOL
```

`prepare-mt5` принимает экспорт M1 из MT5 («Символы → Бары → Экспорт баров»).
Каталог назначения должен быть новым или пустым. Результат:
`prepared/<SYMBOL>-M1-index-YYYY-MM.csv`, `prepared/gaps.csv` и
`quality-report.json`; месяцы разделены по UTC.

Входной заголовок через табуляцию:
`<DATE> <TIME> <OPEN> <HIGH> <LOW> <CLOSE> <TICKVOL> <VOL> <SPREAD>`.
Дата и время имеют формат `YYYY.MM.DD HH:MM:SS`, относятся к началу целой
минуты и строго возрастают. Время сервера трактуется как местное время
`America/New_York + 7 часов` и переводится в UTC; несуществующее или
неоднозначное локальное время отклоняется.

Экспортированный bid OHLC используется без изменения как индексная цена.
Это модель на основе баров MT5, а не восстановленные тики брокера.
`<SPREAD>` и `<VOL>` не используются, `quote_count` берётся из `<TICKVOL>`;
нулевое число тиков отклоняется. Происхождение явно записывается в
`origin="mt5_m1_bars"`, `timezone_conversion` и `index_model`.

Если расстояние между соседними минутами больше 60 минут,
`gap_before_minutes` содержит число отсутствующих минут, иначе — 0.
В `gaps` и `prepared/gaps.csv` попадают такие разрывы, кроме распознанного
закрытия на выходные (пятница → воскресенье/понедельник, не более четырёх
суток по времени сервера). Эти признаки не добавляют отсутствующие строки.

Импорт проверяет `gaps` и `missing_months`, имена файлов, размеры, SHA-256,
схему и порядок минут. В SQLite источник хранится у каждой минуты; разные
источники могут существовать в одной БД. Повторный импорт идентичной минуты
для той же пары и источника не создаёт дубликат, конфликтующее значение
отклоняется. Исходный отчёт качества сохраняется в таблице `imports`.
Бот сам не скачивает исторические файлы; загрузчика истории Upscale нет.

Обратный экспорт выполняется без изменения БД:

```text
python3 scripts/export_sqlite_history.py DATABASE.sqlite NEW_EXPORT_ROOT --runtime-root RUNNER_EXPORT_ROOT
```

Экспорт сохраняет OHLC, разрывы, исходные отчёты в `original-imports.json`,
контрольные суммы и границы строк. Для каждого инструмента требуется один
источник и один исходный отчёт импорта MT5. `data-config.json` в результате
экспорта — справочник путей к наборам; командной опции `--data-config`
у бэктестера нет. `RUNNER_EXPORT_ROOT` задаёт корень, видимый процессу
бэктестера, например внутри Docker.

## Запуск и модель исполнения

```text
forex-backtest swing-history DATA_ROOT SYMBOL PAIR_CONFIG.json NEW_TRADES.csv
forex-backtest swing-replay MT5.csv PAIR_CONFIG.json NEW_TRADES.csv [INDEX.csv INDEX_CONFIG.json]
forex-backtest dxy-build EURUSD.csv USDJPY.csv GBPUSD.csv USDCAD.csv USDSEK.csv USDCHF.csv NEW_INDEX.csv
```

`PAIR_CONFIG.json` содержит один объект параметров инструмента из
`instruments.<SYMBOL>` рабочего `strategy/swing-rules.json`. Выходные CSV
должны иметь новые имена: существующие результаты не перезаписываются.
`swing-history` переводит время UTC в сетку `America/New_York + 7 часов`.
Прямой `swing-replay` читает исходные даты MT5 как время сетки, сохраняя
секунды и пропуски; повторного перевода из UTC нет. Поэтому времена
`signal_t`, `fill_t`, `exit_t` в CSV сделок нельзя читать как UTC.

Сделки исполняет один Swing-движок по диапазону high/low каждой минуты:

- ожидающая заявка отменяется до исполнения, если план завершён или в
  этой минуте достижим её тейк; при одновременном касании входа и тейка
  приоритет у отмены;
- иначе касание лимитной цены исполняет заявку; `cost` один раз ухудшает
  цену входа в направлении сделки;
- для активной сделки сначала проверяется стоп, затем тейк, в том числе
  в минуту исполнения заявки; если достижимы оба, результат — стоп;
- стоп исполняется на заданном уровне с результатом −1R, тейк — на заданном
  уровне относительно риска входа. Дополнительное проскальзывание через
  стоп при гэпе модель не рассчитывает.

Четыре искусственных тика внутри минуты не создаются. OHLC не сообщает
фактическую последовательность внутриминутных касаний; перечисленные
приоритеты — правила модели, а не наблюдённое тиковое исполнение.

Опциональный `reference_exit` поддержан в прямом `swing-replay` при наличии
истории индекса и его конфигурации; `swing-history` явно отклоняет этот
режим. `dxy-build` строит синтетический долларовый индекс только на точном
пересечении времён шести пар. Пустое пересечение отклоняется; отсутствующие
минуты индекса не восстанавливаются. Правила выхода по событиям индекса
описаны в [требованиях Swing](bot-plan/requirements.md).

## Метрики и PDF

`scripts/swing_report.py` строит `report.json` из текущей структуры каталога
запуска и read-only SQLite. Времена сделок переводятся из сетки источника
в UTC; неоднозначное время отклоняется. Общий период задаётся `run-plan.json`:
входы за его концом исключаются, более поздние выходы не считаются
закрытыми в этом периоде. Открытые позиции оцениваются по фактическим M1
close; для портфеля используются только общие минуты инструментов, без
переноса предыдущей цены на отсутствующие минуты.

Время оценки close — начало минуты +59 секунд. Это соглашение отчёта
mark-to-market, оно не добавляет тиков в модель исполнения. Результат в R
отражает сумму результатов при единице начального риска на сделку,
а не доходность денежного счёта со сложным процентом.

```text
python3 scripts/swing_report.py RUN_DIR --database DATABASE.sqlite
forex-backtest --report-only RUN_DIR
```

Первая команда создаёт новый `RUN_DIR/report.json`. Вторая вызывает
`backtest/report/render_swing.py` для сохранённого JSON и создаёт новый
`RUN_DIR/report.pdf`; котировки повторно не прогоняются, метрики не
пересчитываются. Существующий PDF не перезаписывается. JSON сохраняет
проверяемое происхождение данных; PDF отображает эти метрики и ограничения.
