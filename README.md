# Forex: Telegram-бот EUR/USD, GBP/USD и USD/JPY

Лицензия проекта — GNU General Public License v3.0 (`GPL-3.0-only`).
Полный текст находится в [LICENSE](LICENSE).

Rust-бот рассчитывает сигналы по рабочему JSON, отслеживает
вход/стоп/цель и принимает уточнения правил текстом и скриншотами в Telegram.
Реальные ордера брокеру не отправляются. Бот работает только на сервере;
локальный `forex-backtest` использует ту же библиотеку стратегии и формирует PDF.

В репозитории находятся исходники, тесты, инструкции и примеры конфигурации.
Архивы котировок, базы данных, производные отчёты, готовые бинарники и локальный
комплект поставки не включены. Данные подготавливаются отдельно по инструкциям
ниже; сборка выполняется в Docker.

## Правила Swing и общая библиотека

Единственная стратегия приложения — Swing. Рабочие параметры каждой пары
находятся в [strategy/swing-rules.json](strategy/swing-rules.json), публикуемый
[example.json](example.json) содержит тот же формат и параметры. Семейства
`legacy_swing` и `trend_pullback` выбираются внутри Swing; текущие три пары
используют `legacy_swing`. Зоны FVG внутри Swing остаются частью его алгоритма.

Поведение определяют [требования](docs/bot-plan/requirements.md),
[архитектура](docs/bot-plan/architecture.md) и
[план разработки](docs/bot-plan/development-plan.md).
Рабочий JSON един для бота и подготовки конфигураций бэктеста. Серверная копия
после Telegram-правок может отличаться: для её проверки передавайте её явно.
Если рабочего файла нет, создайте его из примера, сохраняя существующий:

```sh
mkdir -p strategy
cp -n example.json strategy/swing-rules.json
```

`STRATEGY_PATH` в [.env.example](.env.example) задаёт путь для сервиса.
У автономных команд путь по умолчанию — `strategy/swing-rules.json`.
Ошибка чтения не подменяет файл примером или встроенными правилами.
`SWING_STRATEGY` и `PRICE_TICK` больше не принимаются: удалите их из настроек.

`forex-core` содержит Swing, загрузку JSON, нейтральные типы свечей, календарь
и агрегатор. `forex-bot` содержит подключения и SQLite. `forex-backtest`
использует тот же Swing и читает исторические минуты.

Поля параметров — `instruments.<SYMBOL>.<параметр>`, вложенные настройки —
`range` и, для соответствующего семейства, `trend_pullback`. Корневые
`comment` и `comments` содержат пояснения и не участвуют в расчётах.
Telegram может менять существующие скалярные параметры и корневые пояснения;
семейство и время старта меняются в файле. Кандидат целиком проверяется перед
атомарной записью. Правка пояснений не пересчитывает планы. Изменение параметров
пары сохраняет уровни опубликованных лимиток и сделок; остальные пары не
переинициализируются. `describe-config` показывает поля и ограничения.

## Разработка и автономные проверки

Команды из корня проекта, без локальной установки Rust:

```sh
docker compose build rust
docker compose run --rm rust cargo fetch --locked
docker compose run --rm rust cargo run -p forex-bot --locked --offline -- check-config example.json
docker compose run --rm rust cargo test --workspace --locked --offline
docker compose run --rm rust cargo run -p forex-bot --locked --offline -- check-config
docker compose run --rm rust cargo run -p forex-bot --locked --offline -- describe-config
docker compose run --rm rust cargo build -p forex-bot --locked --release
```

Тесты читают рабочий Swing JSON. Проверка конфигурации ничего не записывает
и не вызывает внешние сервисы. Rust 1.85.1 и образы закреплены в Dockerfile,
зависимости — в Cargo.lock. После первоначальной загрузки зависимостей тесты
выполняются без сети и ключей. Цели Dockerfile: `dev`, `release`, `backtest`.
Сборка на архитектуре разработчика не подтверждает совместимость с сервером.

## Исторические данные и хранилище

Данные не входят в репозиторий. Пользователь самостоятельно выбирает поставщика,
инструменты и период, получает котировки и подготавливает их для приложения.
Рекомендованных поставщиков и готовых наборов проект не задаёт.

При подготовке сохраняйте происхождение, часовой пояс, единицы цены и сведения
о пропусках. Неоднозначные котировки нельзя исправлять предположениями;
пропуски не следует заполнять вымышленными значениями. Импорт истории в базу
не запускает исторические сделки. Покрытие и стык истории с текущим потоком
необходимо проверять отдельно.

## Локальный бэктест и PDF

```sh
docker compose build backtest
docker compose run --rm backtest --help
```

`swing-history` принимает каталог подготовленных минут одной пары, символ,
JSON параметров этой пары (объект из `instruments`) и новый CSV результата.
Например, после подготовки EURUSD по [формату истории](docs/history-data.md):

```sh
python3 -c 'import json; from pathlib import Path; r=json.loads(Path("strategy/swing-rules.json").read_text()); Path("strategy/EURUSD-replay.json").write_text(json.dumps(r["instruments"]["EURUSD"], indent=2)+"\n")'
docker compose run --rm backtest swing-history \
  data/index-history/EURUSD EURUSD strategy/EURUSD-replay.json \
  reports/backtests/EURUSD-new.csv
```

Создайте родительский каталог результата заранее. Временные конфиги пары нужны
только для конкретного запуска; источником рабочих правил остаётся общий JSON.
Пути входов должны соответствовать read-only mounts в [compose.yaml](compose.yaml).
Контейнер работает без сети; `.env` и серверная БД в него не монтируются.

`swing-replay MT5_M1.csv CONFIG.json NEW_TRADES.csv` принимает исходный M1 экспорт
MT5 на сетке источника. Опциональный `reference_exit` поддерживается только этой
командой с дополнительными `INDEX_M1.csv INDEX_CONFIG.json`. `dxy-build` собирает
такой индекс из шести пар. В live и `swing-history` этот режим отклоняется.
Исторические OHLC — реальные наблюдения рынка, но исполнение сделок по ним
моделируется; последовательность тиков внутри минуты неизвестна.

Для полного текущего комплекта из трёх пар сборщик проверяет `run-plan.json`,
`completion.json`, CSV, конфиги, происхождение и хеши, затем создаёт `report.json`:

```sh
python -m scripts.swing_report reports/backtests/swing-current-20261118 \
  --database data/forex.sqlite
docker compose run --rm backtest --report-only reports/backtests/swing-current-20261118
```

Первая команда требует NumPy и сохранённый комплект входов, указанный в плане
запуска; произвольный CSV не заменяет такой комплект. `--report-only` строит
`report.pdf` из существующего `report.json`, без повторного расчёта сделок.
Существующий PDF автоматически не перезаписывается. Сохранённый отчёт относится
к зафиксированным в нём данным, параметрам и версии расчёта. Удаление отдельного
FVG-движка не меняет его чисел и не требует нового подбора параметров Swing.

```sh
docker compose run --rm --entrypoint python3 --workdir /app/backtest/report backtest -m unittest test_render_swing -v
python -m unittest discover -s tests -v
```

## Настройки серверного демона и автономная проверка

Заполните `.env` по именам из `.env.example`; сам пример ключей не содержит.
Не публикуйте `.env`. Готовый бинарник устанавливается на сервер вручную.
Для автономной проверки Linux-бинарника используйте smoke-test в Docker.
Команда `run` и проверка `probe` выполняются только на сервере. Проверка `probe-upscale` может
выполняться локально через Docker по явному запросу, без запуска демона.
Автономные тесты ключи не читают.

Команды бинарника:

```sh
./forex-bot check-service .env
./forex-bot smoke-test /tmp/forex-smoke.sqlite strategy/swing-rules.json
./forex-bot probe .env
./forex-bot probe-upscale .env
./forex-bot run .env
```

`smoke-test` требует новый путь БД и работает без сети. `probe` читает сведения
о боте, группе и котировках настроенных инструментов; сообщения не отправляет
и OpenAI не вызывает.

## Сборка для сервера x86_64 и установка вручную

Сборка не копирует `.env`, базы данных или архивы котировок в образ:

```sh
docker buildx build --platform linux/amd64 --target release --output type=local,dest=dist/linux-amd64 .
docker run --rm --network none --platform linux/amd64 \
  -v "$PWD/dist/linux-amd64:/check:ro" \
  -v "$PWD/strategy/swing-rules.json:/rules.json:ro" \
  debian:bookworm-slim@sha256:734a72b3d6142a71993b4bc580ca01d8ca687f77a2c422d96a961d3376b179bc \
  /check/forex-bot smoke-test /tmp/forex-smoke.sqlite /rules.json
```

Каталоги установки бинарника, настроек и рабочего состояния выбирает владелец
сервера. Создайте отдельного системного пользователя и настройте systemd unit:
путь к бинарнику и файлу настроек задаётся в ExecStart, рабочий каталог —
в WorkingDirectory. Готовый unit в репозиторий не включён. В примерах ниже
служба называется `forex-bot`; при другом имени замените его в командах.

Создайте в рабочем каталоге подкаталоги `data` и `strategy`, разместите рабочий
JSON по пути STRATEGY_PATH из файла настроек. Относительные пути DATABASE_PATH
и STRATEGY_PATH разрешаются относительно рабочего каталога службы. Каталоги
данных и стратегии должны принадлежать пользователю службы. Файл настроек
с ключами должен быть доступен только администратору и службе (например,
владелец root, группа службы, права 0640).

Существующая SQLite v4 читается с сохранением Swing-позиций, опубликованных
уровней, очереди комментариев и истории сообщений. Поле старого FVG-движка
отбрасывается; неотправленные FVG-сигналы и недельные уведомления снимаются
с доставки. Swing и системные сообщения сохраняют порядок. Незавершённая
операция записи старых FVG-правил явно блокирует переход до её завершения
предыдущей версией. Старые торговые данные в БД массово не удаляются.

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now forex-bot
sudo systemctl status forex-bot
sudo journalctl -u forex-bot -f
```

Проверка реального systemd и перезагрузки выполняется пользователем на сервере.
Локальный smoke-test не заменяет проверку группы, изображений, API и живого рынка.

## Эксплуатация на сервере

Локальный рабочий демон не запускается. Локально выполняются бэктесты, сборка
и автономные проверки. Серверная установка и живые интеграции проверяются отдельно.

Демон пишет в stdout статус каждые 5 минут (последняя котировка UTC, число
открытых Swing-позиций) и итог поиска сигнала после обработки полной закрытой H4. На сервере
просмотр: `sudo journalctl -u forex-bot -f`. Эти строки не отправляются в группу.

При запуске демон отправляет в группу «Бот запущен» с временем UTC.
При временной недоступности Telegram сообщение остаётся в очереди доставки.

## Локальный комплект обновления

Каталог `deploy/` целиком исключён из Git. Он предназначен для отдельно
подготовленного комплекта обновления: бинарника, рабочего JSON, инструкции
конкретной установки и контрольных сумм. После клонирования этого комплекта нет.
Серверные пути и инструкция конкретной установки не публикуются.

## Рабочий JSON и инструменты

Список пар задаётся ключами `instruments`. Изменение правил обновляет Swing
для затронутых пар. Удалённая пара больше не создаёт планы, но её опубликованные
сделки продолжают сопровождаться. Цены котировок хранятся в миллионных долях;
отдельного `price_tick` в конфигурации стратегии нет.

## Пример структуры SQLite

[data/example.sql](data/example.sql) создаёт пустую SQLite-базу формата v4:
таблицы, ограничения и служебные PRAGMA без котировок, сообщений и состояния.
Пример предназначен для новой базы, не для обновления существующей. Приложение
также умеет создавать схему самостоятельно. История импортируется отдельно.
Рабочие базы и остальные файлы data не публикуются.

Подготовка минут из выгрузки MT5: `forex-bot prepare-mt5 <export.csv> <root> <symbol> <source>`.
Импорт подготовленных минут: `forex-bot import-history <db> <root> [symbol]`.
Без symbol используется EURUSD. Поле source отчёта сохраняет реальное
происхождение данных; пустое название источника отклоняется.

### Котировки Upscale

`run` получает индексные снимки Upscale каждые 2 секунды для всех пар одним
запросом. Нужны UPSCALE_API_KEY и ровно один активный API-enabled демо-счёт.
Используется одна индексная цена для свечей и сопровождения сделок.
Параметр `cost` каждой пары задаёт модель издержек на входе. Ордера не отправляются.
`probe-upscale .env` проверяет только Upscale без Telegram/OpenAI и записи в БД;
эту read-only команду можно запускать через Docker локально по явному запросу.

## Единая индексная цена

Единственная цена свечей, входа, стопа, цели и отмены — индекс Upscale.
Котировка содержит symbol, millis (UTC, миллисекунды), price (целое в масштабе
1 000 000) и source. Цена положительна. Старый двухценовой формат не поддерживается.
При исполнении Swing сохраняются его правила входа, стопа, тейка и `cost`;
комиссии и своп отдельно не моделируются. Происхождение исторических данных
сохраняется отдельно: MT5 OHLC не выдаётся за историю Upscale.

Бот восстанавливает сохранённое состояние. При первой загрузке минут SQLite
завершённые исторические сделки не публикуются; открытые позиции помечаются
«Открыта до запуска». Пропуски не заполняются. Формат истории описан в
[history-data.md](docs/history-data.md). Загрузчик истории Upscale не реализован.
